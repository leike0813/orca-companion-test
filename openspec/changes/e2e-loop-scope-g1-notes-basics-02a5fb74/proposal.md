# Proposal

## Why

The repository currently documents itself only through a one-paragraph `README.md`. Contributors have no single place to record working notes, so decisions and open questions get lost between commits. A dedicated notes file gives the project a lightweight, discoverable place to capture that context before the README grows into a full handbook.

## What Changes

- Add a top-level `NOTES.md` that records the project's working notes.
- Define the sections every `NOTES.md` must contain, so entries stay scannable and consistent as the project grows.
- Establish the convention that each note is dated, so the ordering and freshness of entries are obvious to readers.

## Capabilities

### New Capabilities

- `project-notes`: Define the required structure and content conventions for the project's `NOTES.md` working-notes file, including required sections and per-entry metadata.

### Modified Capabilities

None.

## Impact

- `NOTES.md` (new): the only file this change creates or edits; it holds the notes file described by the requirements below.
